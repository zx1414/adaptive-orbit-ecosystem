## 1. 背景与问题

从零重建的 C++17 单线程生态仿真：**环境（蓝细菌/阳光/温度）→ 核（唯一决策体）→ 小球（器官）**。

v2.3.1 是已完成的参考实现，其「菌落器官模型」经用户确认为正确语义：
**核是唯一决策与存储中枢，三类球是功能器官**（侦察球=唯一感知来源、资源球=能量电容、
护盾球=保护进攻，暂占位）。本项目的任务是把它按四层单向流水线重建，并去掉 mod 兼容包袱。

当前实现的偏离（2026-10-31 审计，见 reviews/R5-spec-compliance.md）：
- 球只是"轨道参数"（angle/radius），**不是物理体**，没有世界坐标与速度，无法脱离/被拾取；
- 核能量容量是硬编码常量，**与球无关**；
- 没有侦察球，感知全部来自核本身；
- 食物是抽象撒点，**没有蓝细菌实体**（光合/分裂/产球/连线全缺）。

上述都是需要解决的问题

## 2. 底层规则（完整固化，标注实施阶段）

### 2.1 单一实现（**本项目只做一套**）

- **只有一套新实现**，不存在"平行范式共存"，也不做 `agent_mode` 开关。
- 旧版（v2.3.1）**只作为数学/物理实现的参考资料**：移植其公式与常数，不移植其代码结构，
  也不保留其 mod 生态与逐字节基线。
- 旧版里凡是与新架构冲突的东西（mod 钩子、EventBus、ParamSchema、双模式）
  **一律不带过来**。
- 旧版**有、新版还缺**的机制（例如蓝细菌分裂繁殖、节点连线能量传输）
  应当**按旧版语义重新实现**，而不是当作新发明。

### 2.2 环境层

- **拓扑**：环形（Torus），无边界，全部距离用**最小环距**。
- **生产者（蓝细菌）【初版】**：环境层实体，完整语义参照 v2.3.1（见下方 §2.2.1）。
  - 当前是"定额撒点再生"的抽象食物，**尚未实体化为蓝细菌**——这是最大缺口。
- **地形【后续】**：障碍（阻挡）、水域（耗能更高）、温度区（局部温度偏移）。已实现查询但默认全关。

#### 2.2.1 蓝细菌完整语义（参照 v2.3.1 `docs/archive/CYANO.md`）

蓝细菌是环境层实体，**属于环境，不属于智能体**。它自己有一整套生命周期：

**① 光合与代谢（每帧）**

    energy_gain = photosynthesisRate * sunLevel / (sunLevel + lightHalfSaturation)
    energy_loss = metabolismRate
    net         = energy_gain - energy_loss

- `sunLevel` 来自阳光模型（昼夜周期 + 垂直梯度 + 噪声）。
- 节点能量下限 0；上限无硬性限制（受产球/分裂消耗自然约束）。

**② 分裂繁殖（每帧每存活节点）** —— 这是用户指出的"旧版已有"的逻辑

    if (rng < reproductionProbability && energy >= reproductionCost):
        energy -= reproductionCost
        在 reproductionOffset 范围内生成子节点（能量平分，最小间距检查）

参考默认值：`reproductionCost = 40.0`、`reproductionProbability = 0.01`、
`reproductionOffset = 125.0`、`minSeparation`（最小间距）。

**③ 产球（每帧每存活节点）**

    if (rng < ballSpawnProbability && energy >= ballSpawnCost):
        energy -= ballSpawnCost
        在节点附近生成自由小球（类型随机）

参考默认值：`ballSpawnCost = 30.0`、`ballSpawnProbability = 0.02`。

> 注意：这条说明**蓝细菌会自己产出自由球**——与核产球是两套机制。

**④ 连线能量传输（每 `linkCheckInterval` 帧重算拓扑）**

- 半径 `linkDistance` 内取最近 `maxLinks` 个邻居建立连线；
- 每帧能量从高向低传输，单向上限 `transferRate * (E_high - E_low)`，有死区 `transferDeadband`；
- **传输不产生/消耗能量，只重新分配**。

**⑤ 被核捕食**

    在 predationRadius 内找最近节点
    rawEnergy = 节点当前能量（节点标记死亡，能量归零）
    gain      = rawEnergy * conversionRate * cyanoPreference
    → 入账（EnergyReason::CYANO_GAIN）

**⑥ RNG 纪律（必须照抄）**

- 消耗顺序**固定**：光合噪声 → 连线拓扑（间隔帧） → 产球判定 → 分裂判定 → 产球位置/类型 → 分裂位置。
- 旧版把"色相抖动"放在**独立 RNG**（从种子派生），与主 RNG 隔离——避免视觉参数污染生态确定性。
- 事件：`CYANO_NODE_BORN`（分裂/初始化）、`CYANO_BALL_SPAWNED`（产出自由球）。

### 2.3 探测层（**纯数据层，零逻辑**）

**核心原则（用户 2026-10-31 定稿）**：

1. **每个传感器独立探测**。核与核之间、核与探测球之间**没有共享观测、没有跨单位融合**。
2. 每个传感器**各自按自己的误差**加噪声，加完后把向量传给决策层。
3. 同时把**传感器自身的速度与温度**一并传出。
4. **"看到同一实体怎么加权"是决策层的责任**，不是探测层的。理由：便于后续神经网络学习权重，
   而不是把融合公式写死在感知层。

**传感器类型**：
- **核**：读取一定范围内各实体（类型+位置）与温度。原生感知能力弱。
- **探测球（Scout）**：回传球周围实体信息。**侦察球是菌落对外感知的唯一来源**（v2.3.1 语义）：
  无侦察球 = 只有内部通道（自身能量、边界距离）；侦察球持有量决定感知半径与噪声
  （radius = base + per * sqrt(count)，夹到上限；噪声随侦察数下降）。
  **资源球/护盾球对感知能力零影响**（用户 2026-10-31 明确：资源球不应影响探测）。
  这意味着不构成"囤资源就失明"的取舍——只是资源球**不贡献**感知，而不是**拖累**感知。
- **源**：接收探测层产生的位置信息，作为向量输入。

**双重干扰【初版】**：
- **读噪声**：探测结果的误差，幅度随**速度**单调递增，并被**温度失真**放大。
- **写扰动**：决策输出的向量值被扰动，幅度同样随速度单调递增。

> 当前实现缺陷：读噪声是"每传感器每帧抽一次，全部候选共用同一偏移"，
> 导致候选间相对关系不变、噪声实际不改变排序。**必须改为每候选独立抽样**（见 S16）。

### 2.4 决策层（**纯逻辑层，不认识世界，不用 RNG**）

- 只吃 SensorVector，输出 ActionVector（ActionIntent），**不改任何物理状态**。
- **初版**：手搓死规则 + 打分机制（RulePolicy / StubPolicy / ThermalPolicy）。
- **后续**：感知机 Z = W^T X + b，y = +1 if Z >= 0 else -1（PerceptronPolicy 已实现）。
- 控制类复杂逻辑（如编队）**不做**。

### 2.5 行为层（**唯一物理写点**）

接收意图，与环境和账本交互。所有能量变化必须经 AgentLedger。

**主动行为**：
- 用决策参数决定下一帧核的走法；
- **对球进行控制**（球远了控制会失调）；
- 决定耗能**产生一个小球**；
- 决定耗能**繁殖**（子代初始能量不得超过亲代消耗）；
- 决定耗能**回收小球**使之转为少量能量。

**核对球施力【补充】**：
- 核可以**以能量为代价**，对**范围内**的球（自有球 + 自由球）**施加加速度**。
- 这是主动施力，区别于被动轨道参数。

**被动行为**：
- **呼吸耗能**：与**速度**和**温度**都相关。

### 2.6 资源球语义（用户 2026-10-31 定稿，**A 语义**）

**球是储能仓库**：

    colonyCap = nucleusNativeCap + sum(自有资源球.cap)

- 核的原生容量很小（v2.3.1 默认 30）；能量**只能充到 cap**，采集/收获在 cap 处截断。
- **繁殖门槛 > 原生容量 ⇒ 繁殖必须先囤资源球**（不需要任何额外规则）。
- 资源球失去（被抢 / 脱离 / 被自家核吸收）→ **cap 下降，超出部分立即裁剪销毁**（科目 CapOverflow）。
- 自家资源球贴核被吸收 = "吃掉电池换零食" —— orbitRadius 基因因此成为**负载基因**
  （好基因组会把资源球停在核外轨道上）。进食与储能的张力由此涌现。

**球受力学控制，自然脱离**：

- 球有**世界坐标 + 速度**，被核的力场（径向弹簧 / 切向驱动）吸引环绕。
- **脱离是力学的结果，不是一条"掉落"指令**。球距核超过阈值即脱离。
- **脱离后（A 语义）**：
  - **能量仍在球里，随球移动** —— 核失去的是**支配权**，不是能量蒸发；
  - **不调用 dissipate**（拒绝 B 语义"掉落即蒸发"）；
  - 变成**自由球**（ownerId = 0），位于世界坐标；
  - **可被任意核捡走**（adopt），ledger.transfer(ballId, newOwnerId, ...) 零和；
  - 自由球随时间衰减（ballDrift），**这才是真正的掉落损失**。

### 2.7 温度偏好【后续深化】

- 温度偏离最适越远，感知与决策失真越严重。
- 初版只实现"失真度影响读噪声幅度"，梯度验收留后续。

## 4. 范围边界（非目标）

- **不做 mod 兼容**：旧版有 mod 生态与逐字节基线，新版**只有一套实现**，不保留这些包袱。
- **暂不做有性繁殖**。
- **不做 `agent_mode` 双模式**：只做一套自治体范式。
- **不实现复杂控制类**（如编队）。
- **护盾球只保留类型与计数，不实现功能**（拦截/撞击属战斗重做）。
- **不做旧版的兼容**：前端是**参考实现**，不是逐像素克隆；旧版有的功能要有，但布局、交互、技术选型可重做。
- **不把决策做成"查表"**：全局感知会让决策退化成查表，这是 v2.3.1 已记录的否决理由。

## 6. 约束与红线

- **能量红线**：光合是唯一 injectPrimary；所有能量变化经 AgentLedger；每 tick 审计，
  失败即终止（退出码 3）。任何绕过账本直接改能量字段的写法视为失败。
- **架构红线**：环境 → 探测 → 决策 → 行为严格单向。探测不调用策略；决策不读世界、不使用 RNG；
  行为是唯一写实体状态的层。tools/check.ps1 的依赖守卫必须通过。
- **确定性**：单线程、PCG32、固定迭代顺序、稳定 EntityId。禁止 rand() 与时间种子。
  传感器噪声必须来自 Simulation 持有的 PCG32。
- **零第三方依赖**，MSVC /W4 /WX /permissive- /utf-8 零警告。
- **错误码契约**：2 参数错误、3 审计失败、4 I/O 失败、5 快照无效。
- **枚举只追加**：EnergyReason 只能在末尾加项，计数与名字表三处同步（static_assert 保护）。
- **命名空间隔离**：新类型一律 namespace agentsim。
- **frontend/ 与 C++ 侧解耦**：前端只消费 JSON 轨迹契约，不调用模拟器进程、不引入服务器、不引入任何第三方库/CDN。
  C++ 侧只保证契约稳定；前端不得反向依赖 `src/` 的内部实现。
- **参数必须真实生效**：任何 CLI 参数/配置键，改它必须能观察到输出变化；否则是死参数，视为缺陷。

## 7. 关键术语

- **蓝细菌（CyanoNode）**：环境层的生产者，唯一进行光合的实体。
- **核（Nucleus）**：消费者与唯一决策体，携带可遗传参数。
- **小球（Ball）**：核的器官，不决策；类型 Resource/Scout/Shield，决定功能不决定力学。
- **侦察球（Scout）**：探测的唯一来源；持有量决定感知半径与噪声。资源球不影响感知。
- **资源球（Resource）**：能量电容；colonyCap = nativeCap + Σ球.cap。**不影响探测能力**。
- **自由球（Free Ball）**：ownerId = 0，位于世界坐标，可被任意核拾取。
- **轨道半径（orbitRadius）**：核的遗传参数，同时是**负载基因**（球停得远则储备多、吸取慢）。
- **菌落容量（colonyCap）**：nativeCap + Σ自有资源球.cap，超出部分销毁记 CapOverflow。
- **双重干扰**：读噪声（探测结果）+ 写扰动（决策输出），强度都随速度递增。
- **审计恒等式**：injected − dissipated == Σ蓝细菌 + Σ核 + Σ球。
- **点开即玩**：单个 HTML 文件，双击用 `file://` 打开就能跑，不需要 http 服务器、不需要 npm build、不需要联网。
