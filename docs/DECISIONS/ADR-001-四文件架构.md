# ADR-001 —— 采用四文件架构与 GOAL 详实化规格

## 背景

项目此前用 `docs/HANDOFF.md` + `docs/ROADMAP.md` + 各里程碑 PLAN 文档承载目标与进度。
后果是：目标散落在多个文件，`HANDOFF.md` 同时承担"当前状态"和"目标描述"两种语义，
导致一次严重的语义漂移——`ARCH.md` 曾把"不包含 Ball/Nucleus"写成规范，而它实际是
M1 偏离原始设计的**症状**，后续接手者据此继续往错误方向走。

同类问题还有：M4.5 的设计纠正记录在 ROADMAP 里，但 HANDOFF 的"下一步"仍指向 M5 神经网络；
BALANCE.md 的平衡数据在被废弃的模型上测得，却仍被当作金标准引用。

## 选项

1. **维持现状**：继续用 HANDOFF/ROADMAP/PLAN 三套文档。成本为零，但已经证明会导致语义漂移，
   且无法回答"哪条证据对应哪条目标"。
2. **只加一份 STATUS.md**：单一状态文件，但目标仍散落。解决不了"目标唯一"问题。
3. **四文件架构**：`GOAL.md`（唯一目标源，七节结构 + 编号成功标准）、`TODO.md`（唯一状态源，
   四态分区）、`INDEX.md`（可执行证据表）、`DECISIONS/`（ADR，有门槛）。

## 决定

采用选项 3。核心理由是**把"要什么""做到哪""凭什么说做到了""为什么这么选"拆成四个
互不重叠的权威源**，每条规则只在一个文件里维护，其余文件只能引用编号。

配套约束：
- GOAL 的成功标准必须编号（S1、S2…），阶段退出条件只能引用编号，禁止"基本完成"。
- INDEX 的每条证据必须能跑、能指、能 diff；无证据不得标记完成。
- DECISIONS 设收录门槛（可逆性低、影响面大、有争议），避免退化成流水账。

## 后果

正面：
- 目标变更必须走 GOAL 的修订记录，旧目标可追溯，不会再出现"文档描述的是症状却被当成规范"。
- 任何"完成了"的声明都能被一条命令反驳，口头结论失去效力。
- 阶段边界变硬：未满足退出条件不得宣称进入下一阶段。

负面：
- 每次任务循环多三步（补 INDEX、移 TODO、必要时写 ADR），短期开销上升。
- 四文件之间可能不一致，需要定期对账（已在 TODO 中约定每 Phase 一次）。
- 已有的 HANDOFF/ROADMAP/ARCH 与新架构并存，存在双份描述的风险，需要后续收敛。

## 可逆性

**中等偏低**。四文件本身是纯文档，删除成本低；但一旦团队习惯了"无 INDEX 证据不算完成"
这条规则，回退到口头汇报模式会显著降低可信度。迁移成本主要在补历史证据，不在文件本身。
