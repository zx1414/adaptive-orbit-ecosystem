## 4. 参数有效性：--policy 真实改变输出

同 seed、仅改 `--policy` 的两组对照（CSV 原行）：

**组 1：seed=42，rule vs stub** —— nuclei 相同（24），food 与 total_energy 明显分化：
```
rule,42,...,nuclei=24 food=0 total_energy=12361.71745248 policy=rule
stub,42,...,nuclei=24 food=53 total_energy=12571.60529212 policy=stub
```
**组 2：seed=123，perceptron vs thermal** —— 同参数下一条灭绝（exit 5）、一条繁荣（exit 0）：
```
perceptron,123,...,nuclei=0 food=15 total_energy=9245.31495533 audit=ok exit=5
thermal,123,...,nuclei=24 food=2 total_energy=12774.56870339 audit=ok exit=0
```
结论：`--policy` 非死参数——它同时改变 food/total_energy 轨迹乃至生死结局。

## 5. 已知局限

1. **每格单次运行**：每 (policy, seed) 只跑一个 20k 轨迹，无重复采样，均值两侧无置信区间；7 个幸存策略的 total_energy 排名在 sd 量级内，**统计上不可区分**。
2. **nuclei 顶格截尾**：kMaxNuclei=24 使所有幸存者饱和，生存质量差异被截断（只能靠 food/TE 间接观察）。
3. **seed 只有 6 个**：对"灭绝"这类布尔结局尚可（6/6 vs 0/6 已是决定性），对连续指标（TE/food）分辨率不足。
4. **计时含进程启动与 stats 落盘**（Windows 计时噪声 ±20%），elapsed 只用于量级参考。
5. 灭绝 tick 为 10-tick 采样分辨率，真实灭绝时刻有 ±10 tick 误差。

## 6. 下一步建议

一句话：把 `--nuclei` 初始上限或 `kMaxNuclei` 提到 100+ 并加多组重复 seed，用"到顶用时 + food 压力曲线"区分 7 个幸存策略的真实强弱，同时对 perceptron 做 `--perceptron-seed` 扫描验证"裸初始化必灭"是否普适。
