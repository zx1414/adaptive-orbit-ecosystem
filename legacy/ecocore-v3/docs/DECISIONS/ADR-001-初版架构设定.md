- 状态：已接受（Accepted）
- 日期：2026-10-31
- 关联：GOAL.md §1.1 底层规则、§5 阶段路线；上游 `docs/SPEC-SOURCE.md`
- supersedes：无；被 supersede：无

## 背景

agentsim 从零起步。用户原始规格（SPEC-SOURCE.md）同时给出了大量"最终形态"机制
（感知机决策、地形三件套、温度偏好失真、探测球回传）与"初版就要"的机制
（Torus、食物、手搓规则、速度关联双重干扰、能量闭环）。若按最终形态一次性设计，
初版无法运行、无法验收；若过度裁剪，又会砍掉决定架构形状的机制（拓扑、干扰注入点）。
因此在写第一行代码前，须对三个低可逆、大影响的取舍作出决策并留档。

## 决策 ① 启用环形拓扑（Torus）

### 选项

- A. 平面矩形世界 + 边界反弹/夹紧：实现最直觉。
- B. 平面世界 + 出界环绕传送，但距离不取最小环距：省事但语义错。
- C. Torus 环形拓扑，所有距离用最小环距。

### 决定

采用 C。初版坐标系统即按环形包裹实现；距离函数只有一个：最小环距（验收 S1）。

### 后果

- 好处：不存在边界特例代码；实体运动、探测、食物生成天然均匀；
  后续地形与温度区直接铺在环面上，不需要改拓扑。
- 代价：所有位置差、距离、相对向量必须走 wrap 函数，裸欧氏距离调用视为缺陷；
  单测必须覆盖跨边界用例。
- 风险：探测向量中的"相对位置"若忘记 wrap，会在边界附近产生错误决策——由 S1 单测 + 守卫约束。

### 可逆性

低。坐标与距离语义渗透到全部模块，后期更换拓扑等于重写环境层，故现在定死。

## 决策 ② 双通道速度干扰（读噪声 + 写扰动）

### 选项

- A. 只对探测读数加噪声，决策输出保真：实现减半。
- B. 读、写两通道都加扰动，且强度与速度单调挂钩（速度越快干扰越强）。
- C. 干扰强度固定、与速度无关。

### 决定

采用 B。读通道（探测结果）与写通道（决策输出的向量值）分别叠加扰动，
强度函数对速度单调递增（验收 S6）；初版为基础版（简单幅度模型即可），深化留后续。

### 后果

- 好处：机制成为"快速移动有代价"的物理直觉的一部分，与呼吸耗能共同约束无脑狂奔；
  为后续温度偏好失真（同样作用于感知与决策）预留了同一注入点。
- 代价：所有噪声必须出自自传 RNG 并纳入确定性体系，否则 S2（固定种子双跑逐字节一致）立刻失败；
  单测需证明强度随速度单调（S6）。
- 风险：干扰幅度过大让初版闭环无法收敛；参数先保守，可调。

### 可逆性

中。注入点（探测出口、决策出口）固定不可逆；幅度模型与噪声形状可调可换。

## 决策 ③ 舍弃感知机与地形，先跑通核心闭环

### 选项

- A. 初版即实现感知机 + 地形 + 温度区，一步到位。
- B. 初版只做手搓打分规则（RulePolicy）+ 无地形 Torus，最小闭环跑通后按 Phase 叠加。
- C. 连双重干扰也推迟，先做纯确定性吃食物。

### 决定

采用 B。初版决策层只有 `IDecisionPolicy` + `RulePolicy`（打分机制），
严禁任何神经网络（验收 S8 守卫）；地形（障碍/水域/温度区）整体推迟【后续】。
双重干扰保留基础版——它决定架构形状，不能像地形一样推迟，故不选 C。

### 后果

- 好处：Phase 1 每个任务都有可执行验收（S1–S11，S9 除外），由简到难，闭环尽早可复现；
  感知机之后成为 `IDecisionPolicy` 的第二个实现、地形之后成为环境层的附加数据，
  均不需要推翻既有结构。
- 代价：初版行为看起来"笨"（打分规则 + 基础干扰），这是接受的展示代价。
- 风险：SensorVector 字段设计若不留扩展位，后续温度/地形特征要改接口——
  在 T04 实现时预留字段顺序约定以降低返工。

### 可逆性

高。这是排序决策而非结构决策：感知机与地形按 Phase 4/5 路线随时可加；
唯一不可逆的承诺是"决策层只吃 SensorVector"的接口形状。
