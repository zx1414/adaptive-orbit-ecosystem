# 目标重定义：一个"合理的、自然的自涌现生态系统"

用户的话："目的是实现一个合理的自涌现生态系统，要自然。注意灵活。"

这段覆盖了"向旧版看齐"的表述方式——旧版是**参考**，不是评分标准。真正的验收标准是下面这些
**生态学判据**。任何实现细节都要接受这几条的检验；与它们冲突的"对齐"没有意义。

## 一、验收判据（硬，可测量）

### 1. 能量收支紧平衡，不膨胀
- `injected` 与 `dissipated` 的**每 tick 差值**必须与 `sumLiving` 的变化对得上（这是已有审计）
- 但光有审计不够：**总能量水位不能单调上升**。跑 100k tick，总能量时间序列的线性回归斜率
  必须 ≈ 0（相对值），或者呈现真实的周期波动（受昼夜/季节驱动）
- 判据：`|slope| * ticks / mean(total) < 0.15`

### 2. 种群在承载力附近波动
- 核数量时间序列：不能单调涨到上限然后平台，也不能单调跌到 0
- 必须是"上冲-回落-再上冲"的波动，或稳定的稳态附近的噪声
- 判据：最后 20% tick 的核数标准差/均值 ∈ [0.05, 0.6]；且 100k tick 内**没有灭绝**（nuclei > 0）
- 三个不同种子都要满足

### 3. 遗传多样性不塌缩
- 基因组 24 个参数，每个参数在种群内的标准差必须 > 初始标准差的 30%
- 判据：跑 50k tick 后，至少 **18/24** 个参数的种群标准差 > 初始值 × 0.3
- 反例（当前状态）：所有核基因相同 → 标准差恒为 0 → 不满足

### 4. 谱系分化可观测
- 色相 hue 必须真的发散：种群 hue 的圆标准差 > 30°（初始约 8°）
- 且能观察到至少 **2 个可区分的策略簇**（用 2-3 个主基因做聚类，如 maxSpeed vs energyThreshold）
- 判据：手工检查 trace 里 50k tick 时的参数散点图，能看到分群而不是一团

### 5. 蓝细菌是第一营养级，且稳定
- 蓝细菌数量与核数量要有**相位关系**（捕食者-猎物振荡），或者至少负相关
- 判据：100k tick 里两者时间序列的皮尔逊相关系数 < -0.2，或者存在明显的相位滞后
- 蓝细菌不能灭绝（否则食物链断裂）

### 6. 玩家调控真的能改变演化方向
- 把 light 轴从 0 调到 4，跑 20k tick，核的平均 `cyanoPreference` 必须**显著变化**（> 10%）
- 把 pressure 轴从 0 调到 4，核的平均 `maxSpeed` 必须显著下降（压力 = 代谢贵）
- 判据：这是"涌现"的定义——调控不是直接改数值，是改变选择压力

## 二、灵活原则（怎么在冲突时判断）

1. **自然 > 对称**：真实的生态是不对称的、有噪声的、有滞后的。不要为了"优雅"把机制做成对称可逆的。
2. **局部信息 > 全局信息**：核只能感知自己附近。任何"全体广播"式的机制都要质疑。
3. **代价必须真实**：任何能力都要有能量代价，且代价非线性（越快越贵、越大越贵）。
4. **冗余要有用**：如果两个机制效果重叠到分不出差异，删掉一个。
5. **参数不是魔法**：不能靠"调到一个刚好不爆炸的数"来维持平衡。平衡应该来自反馈回路
   （负反馈：多了就饿死，少了就繁盛），不是来自常数。
6. **能删就删**：规格里如果有实现后发现是死参数/死分支的东西，删掉并记录，不要留着占位。

## 三、当前已知的生态问题（必须先修）

1. **能量水位 26k-29k 且持续上升**（旧记录）——光合无上限注入，捕食消费被封顶（`kReproCap=24`）
   → 注入 > 消费，必然膨胀。这是最严重的问题。
2. **所有核基因相同**（基因组尚未接线）→ 没有选择，没有涌现。
3. **蓝细菌 64 节点硬上限**是性能护栏，但它同时是生态天花板——需要评估是否该换成
   "能量不足自然饿死"的自然约束，而不是硬截断。
4. **捕食是 25% 随机触发 + 固定比例**——不是"核想吃多少吃多少"，而是"系统随机喂你"。
   这不符合"自然的自涌现"：捕食强度应该是核的基因（cyanoPreference/cyanoDigestion）决定的。
5. **繁殖上限 kReproCap=24** 是硬编码的承载力量，应该由能量供给自然决定，或至少可配置。

  让他们在实现时提出替代方案，回报理由。
- **干一晚上不停**：R1→R5 只是骨架顺序，不是硬边界。发现更好的结构可以调整。
- **灵活**：如果某个规格实现出来不自然，改规格，不要硬做。
  但改规格必须写进 docs/LOG.md 并说明"为什么这个规格是错的"。
- **不许为了填槽位派活**：每一轮都必须有明确的生态学目标。

## 修订 1（2026-11-01 20:00，Round 3）：判据 1/5 的测量窗口

**问题**：判据 1（能量紧平衡）现规定全窗口线性回归。但 512² 世界 + 密度等比（T53/T56）后，
开局是"半空世界"——12 核播种进 4 倍面积，种群要用数千 tick 向承载力爬坡（ colonization phase）。
全窗口斜率测的是**殖民速率**，不是**平衡漂移**。seed42 实测：末窗（最后 30%）斜率
+1144/1000t 看似膨胀，实为种群 299→375 的填满过程；人均核能 43→54 无失控迹象。

**修订**：
- 判据 1 改为**末 30% 窗口**的 `|slope| × windowTicks / mean(windowTotal) < 0.15`。
  全窗口斜率仍计算并报告（作"殖民速率"参考），但不作为判据。
- 前提：窗口内种群自身接近稳态（末 30% 的核数线性趋势 |slope| < 种群均值的 5%/kt）。
  若种群仍在单调爬坡，判据 1 输出"DEFER（未稳态）"而非 FAIL——用错尺子量未稳态系统
  得到的 FAIL 是噪音，不是信号。
- 判据 5 的"负相关或滞后过零"同理：殖民期捕食者与猎物**必然**同向增长（更多核 → 更快
  消灭蓝细菌，但蓝细菌总盘也在扩张）。滞后过零检测只在平台期有物理意义。同上，未稳态
  时输出 DEFER。

**为什么这不是放宽标准**：判据的本意是"平衡时不膨胀"。量一个正在填满的世界并判它 FAIL，
既测不出膨胀也测不出平衡。修订后，系统必须先证明自己到了平台期，然后接受与原先完全
相同强度的平衡检验（0.15 阈值不变、-0.2 阈值不变）。稳态本身由判据 2 的 cv 窗口与
"种群末窗趋势 < 5%/kt"共同把关。

**三种子现状**（修订口径下的预期）：
- seed42 10k：末 30% 种群趋势 +30.9/kt（≈均值 340 的 9%/kt）→ 仍 DEFER，需更长跑或 R9-A 后复测
- seed7 8k：撞 maxNuclei=600 护栏（19/160 帧 cap-hit）→ 护栏介入使"稳态"失真，T57 候选立项
- seed123 8k：204 核未撞护栏，斜率 +596/kt 收敛中 → 最有希望先到稳态的种子

**T57 立项**：maxNuclei=600 护栏在 512 世界被 seed7 撞顶。选项：
(a) 护栏提到 800（O(n²) 性能代价实测：600 核 ≈ 8k tick/474s，800 核 ≈ +78%/tick ≈ 14min/8k）；
(b) 不提护栏，把撞顶当作"承载力由能量决定"机制的未完成证明（撞顶 = 消费端仍弱于供给端）；
(c) R9-A 迁移回报提高移动成本，自然压低承载力。
倾向 (c)+(b)：先看 R9-A 效果再定，护栏是最后手段。
