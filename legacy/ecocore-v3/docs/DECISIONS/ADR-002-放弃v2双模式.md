# ADR-002 —— 放弃 v2 的 mod 兼容与 agent_mode 双模式

## 背景

`docs/archive/PLAN_AGENTS.md` 的原始设计要求：新范式与 v2 的"轨道范式"**长期共存**，
由 `WorldConfig::agent_mode` 切换，`agent_mode=0` 时轨道管线"一行行为逻辑都不许变"，
以保证 v2.3.1 release、mod 生态与基线金标准不受影响。

实际历史是：v3 的 M1（`cbe93a1`）是推倒重来，直接删掉 v2 源码并替换了生态本体，
`agent_mode` 从未实现。到了 M4.5 需要决定后续路线时，"是否补回双模式"成为必须回答的问题。

## 选项

1. **补回 `agent_mode` 双模式**：忠实执行原始设计。代价是 `World` 里长期存在两套实体、
   两套管线、两套快照格式；任一模型的改动都要考虑另一模型不被污染。
2. **只保留新模型，放弃 v2 兼容**：单一模型，但 v2 的 mod（`ball_roles`、`ball_loss_relief`、
   `lucky_lottery` 等按轨道语义编写）全部失效，基线金标准作废。
3. **保留 v2 模型，放弃新模型**：等于放弃本次重构目标。

## 决定

采用选项 2。用户明确指示："彻底放弃 v2 的 mod 兼容和基线金标准，以实现我要求的生态系统为目标。"

判断依据：
- v2 的轨道模型与目标模型在**实体语义**上就不同（v2 的 Ball 无能量，新模型的球是储能容器），
  不是同一套代码开个开关能切换的。
- 双模型共存会让"哪个是当前真相"长期模糊，而这正是 ADR-001 要解决的问题。
- mod 生态的价值低于"生态模型正确"这一目标。

## 后果

正面：
- 实体模型只有一套，`src/agents` 与 `src/producers` 可以被彻底删除（已完成）。
- 快照格式可以按菌落模型直接重写，无需兼容 v1。
- 调参与验收只需针对一套语义。

负面：
- v2.3.1 的 mod 与基线金标准永久失效，不能作为回归参照。
- 失去了"新旧对比"这一发现实现偏差的手段——这一点在 M5 期间已经造成过代价：
  移植轨道物理时曾因未逐函数对照 v2 源码，写出了积分顺序错误与缺失位置积分的实现。
  补救方式是保留 `legacy-v2.3.1` 标签作为**语义参照**（不是运行参照）。

## 可逆性

**低**。代码删除与模型替换已经落地，v1 快照格式已不再被接受。若要恢复双模式，
需要重新引入 v2 实体、管线、快照格式与 mod 钩子，成本接近重做。
