# 对抗式审查协议

目标：不让实现者自证正确。实现与审查由不同子代理在隔离上下文中完成；审查者从反例出发，
而不是从作者的实现说明出发。主 agent 只负责契约、仲裁和最终门禁。

## 1. 角色

| 角色 | 谁来做 | 职责 |
| --- | --- | --- |
| Lead / 指挥 | 主 agent | 写契约与验收、拆任务、仲裁 P0/P1、跑最终门禁、提交 |
| Generator | 子代理 A | 实现一个小切片，同时写正常测试与对抗测试；不审查自己的 diff |
| Red Team | 子代理 B | 隔离上下文，只拿契约 + diff + 测试结果，目标是证明实现是错的 |
| Verifier | 子代理 C 或主 agent | 干净构建、单测、check、acceptance；不改代码 |

主 agent 可以写关键代码，但不能既写实现又充当唯一审查者。

## 2. 流程

1. Lead 写清契约：目标、允许改的文件、不变量、验收命令、失败退出码。
2. Generator 实现 + 自测；提交前给出 diff、测试命令、已知风险。
3. Red Team 在**新上下文**中审查；输入只给契约、diff、测试输出，不给作者的解释。
4. Red Team 尽量写出失败用例或复现命令；不能复现的猜测标 P2。
5. Generator 修 P0/P1；Red Team 复审同一批问题。
6. Verifier 在干净工作树上跑全量门禁；Lead 提交。

## 3. 隔离规则

- Red Team 的提示词里不要出现“我已经实现了”“这个设计是合理的”等作者叙事。
- 不把 Generator 的思考过程、聊天记录、设计辩解转给 Red Team。
- 只有一个子代理时，必须分两轮、两个角色提示词：
  - 第一轮：实现 + 自测；
  - 第二轮：清空作者视角，明确“你是红队，目标是找出 P0/P1，不要维护原实现”。
- 审查者可以读源码，但不能改代码；修复由 Generator 或 Lead 完成。

## 4. 审查输出格式

每条一行：

    [P0/P1/P2] 文件:行 — 触发条件 — 期望/实际 — 最小修复

- P0：编译失败、UB、能量不守恒、确定性破坏、读档不一致、数据损坏。
- P1：边界错误、错误被静默吞掉、验收缺失、可复现的逻辑漏洞。
- P2：可维护性、命名、注释、非关键性能。
- 不报纯风格意见；不写“整体不错”之类总结代替问题。
- 能复现的必须给命令或最小输入。

## 5. M3 对抗清单

### 快照格式

- magic 错误、version 过高/过低、文件截断、追加垃圾字节、长度字段撒谎。
- 计数为 0、负数、超大值、总字节数溢出。
- NaN/Inf 的能量、位置、速度、基因；cap<=0；重复 EntityId；nextId 小于已有 id。
- 空文件、只读文件、目录路径、磁盘写入中途失败。

### 状态完整性

- tick 0 存档；繁殖发生的同一 tick 存档；死亡结算后立刻存档；RNG 缓存 normal 非空时存档。
- 0 生产者、0 Agent、达到 max、有死亡残留、账本有未清零原因统计。
- 读档不得调用 injectInitial；账本统计与实体能量必须同时恢复；读档后立即 audit。
- 存档前后 stateHash、总能量、producers/agents、injected/dissipated、审计一致。
- 10k 存档 + 10k 续跑 与 20k 直跑逐字段一致；同一 seed 双跑一致。

### 工程

- CLI 新参数不破坏旧参数；失败返回明确非零码；不崩溃、不静默成功。
- /W4 /WX 零警告；CMake 与 build.ps1 都能构建；依赖守卫不退化。
- 新测试必须能在干净构建上失败于修复前、通过于修复后（至少逻辑上可复现）。

## 6. 提示词模板

### Generator

    你是实现者。只改以下文件：<list>。
    契约：<invariants + acceptance>。
    必须同时添加正常测试与对抗测试；不要修改测试来迁就实现。
    完成后输出：diff 摘要、测试命令、已知风险。不要宣称“已完成”而不给证据。

### Red Team

    你是红队审查者，目标是证明这份实现是错的。你没有参与实现，不要维护它。
    只读，不改代码。输入：契约、diff、测试输出。
    重点：UB、能量不变量、确定性、边界、错误处理、读档一致性。
    输出最多 10 条：[P0/P1/P2] 文件:行 — 触发 — 期望/实际 — 最小修复。
    能复现的给命令；不能复现的标 P2。不要写总结性表扬。

### Verifier

    你是验证者。不要改代码。在干净工作树上运行：
    tools/build.ps1、unit_tests.exe、check.ps1、acceptance.ps1、CMake+CTest。
    报告每项退出码与失败日志；任何一项失败即整体失败。

## 7. 主 agent 的边界

- 必须自己掌握：架构红线、能量不变量、最终验收、提交。
- 应交给子代理：实现切片、测试扩展、格式/边界审查、性能实验、文档校对。
- 子代理结论必须抽样复核；P0/P1 必须自己看 diff 和复现。
- 子代理链路不稳：失败重试、缩小任务、必要时中断后接手，不阻塞主线。
