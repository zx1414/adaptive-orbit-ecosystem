# M2.5 设计：低于硬上限的稳定共存

目标：让生产者与 Agent 的平衡点由资源竞争、密度依赖繁殖和饱和收获决定，而不是由
`ProducerConfig::max` / `AgentConfig::max` 硬性截断。

## 1. 模块边界

- 新增 `sim::Simulation` 作为唯一组合根，持有 Environment、EnergyLedger、Random、
  ProducerSystem、AgentSystem，并实现 `world::WorldQuery` 与 `world::Forage`。
- `agents` 只依赖 `world::WorldQuery`（只读查询）和 `world::Forage`（按 id 收获），
  不再 include `world/World.h`。`producers` 只依赖 core 与 world 的账本/环境接口。
- app 依赖 sim；sim 依赖 world/producers/agents。删除 `src/world/World.*`。

## 2. 机制

### 2.1 生产者局部光竞争

对生产者 i，用 SpatialIndex 查询 `interactionRadius` 内的邻居（排除自身，按 id 稳定顺序）：

    localDensity_i = 邻居数
    localBiomass_i = sum(邻居 energy)
    shading = 1 / (1 + crowding * localDensity_i + competition * localBiomass_i / cap_i)

`gain = photo * light * (1 - energy/cap) * shading`。

- `crowding` 保留 M2 语义；`competition` 为 0 时行为与 M1/M2 完全一致。
- 邻居能量从 id→Producer* 映射读取实时值；索引只用于候选集，保证 O(邻居数)。

### 2.2 生产者密度依赖繁殖

    threshold = repro * (1 + densityRepro * localDensity_i)

只有 `energy >= threshold` 才繁殖。`densityRepro = 0` 时退化为固定 `repro`。
高密度处阈值升高，先停止出生，而不是等 max 拦截。

### 2.3 Agent 饱和收获（功能反应）

    food = max(0, target.energy - reserve)
    intake = harvest * food / (food + halfSaturation)     (halfSaturation > 0)
    intake = min(intake, food)                            (halfSaturation = 0 时即 M1 线性)

保留 `harvestReserve`，最后一份猎物能量不被采空。收获仍走 `EnergyLedger::transfer`，
耗尽时由 `Forage` 实现 kill 并记 `ProducerDeath`。

### 2.4 Agent 密度依赖繁殖

    threshold = repro * (1 + densityRepro * localAgentDensity)

`localAgentDensity` 为 `densityRadius` 内存活的其他 Agent 数（排除自身，索引候选 + id 映射）。
配合 `lifespan` 的死亡周转，形成低于 max 的出生/死亡平衡。

### 2.5 弱化硬上限

标定配置使用 `--producer-max 1000 --agent-max 1000` 作为数值安全阀；默认配置仍为 300/200，
保证 M1/M2 基线不变。

## 3. 确定性与不变量

- 所有空间查询结果按 EntityId 排序后使用；id→实体映射只做查找，不迭代。
- 随机数仍只来自 World/Simulation 持有的 PCG32；生产者的出生角度/距离、Agent 出生位置使用 RNG。
- `decide()` 仍禁止 RNG。
- 所有能量变化经过 EnergyLedger；每 tick 审计；同 seed 双跑状态哈希一致。
- `competition/densityRepro/halfSaturation = 0` 时，默认路径保持原行为。

## 4. 性能

- `Simulation::queryProducers/queryAgents` 改为走 SpatialIndex，再用 id→实体映射读取实时
  energy/cap；`Forage::harvest` 用 id 映射 O(1)。
- Sensors 对候选集只做一次扫描取最近两个（距离相同按 id），不做全量排序；复用 scratch 缓冲。
- 索引 cellSize 取 200（2000×2000 世界为 10×10 网格），减少半径 800 查询的空 cell 遍历。
- 目标：默认 500 实体、20k tick < 20 秒（改造前约 100 秒）。

## 5. 验收

- seed 42/7/123，各 20k tick：生产者与 Agent 均不灭绝；审计每 tick 通过。
- 5k tick 预热后，至少一个种群 >=80% 采样点低于其上限的 80%。
- 同 seed 双跑状态哈希一致。
- 推荐配置 50k tick 耐久通过。
- 结果写入 docs/BALANCE.md，CSV 保存在 build/acceptance/。

实测（1000/1000 安全阀）：seed 42/7/123 的 20k 结果为 202/43、214/111、255/71；seed 42 的 50k 为 202/65；
两个种群 100% 采样点低于 800；tools/acceptance.ps1 14 项全 PASS；默认 20k 性能约 15.9 秒。
