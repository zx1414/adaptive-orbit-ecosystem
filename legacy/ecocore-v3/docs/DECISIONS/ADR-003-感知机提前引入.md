# ADR-003 感知机提前引入

- 编号：ADR-003
- 状态：已接受（Accepted）
- 日期：2026-10-31
- 关联：GOAL.md S8（本 ADR 重定义）、S13（保留为 P4 出口）、§1.1 R4.2、§4 非目标、§5 阶段路线、§6 流程红线；TODO.md T16；ADR-001；docs/experiments/E1-perceptron-evolution.md
- **Supersedes：GOAL.md §4 非目标中的「初版不写感知机/神经网络」与 §5 Phase 1 禁止领取条款**（"未满足退出条件不得进入下一阶段，也不得在 TODO 提前挂下一阶段任务"）；§1.1 R4.2 行文保留原状，其"初版出现即违规"的判罚语义由本 ADR 改判；被 supersede：无

## 背景

用户明确指示："如果干完了就自己创新（比如写各种决策策略），我们有充足的时间和 token"。主代理据此提前实现了 GOAL §1.1 R4.2【后续】标注的感知机策略 PerceptronPolicy：

- 公式 `Z = W^T X + b`；`y_hat = sign(Z)`（Z=0 取 +1）；`decide` 无 RNG；权重可 `serialize`/`deserialize`（位精确往返单测）。
- 已接线 CLI：`--policy perceptron` / `--perceptron-seed` / `--perceptron-scale`（`src/app/Cli.cpp:105-127` 解析，`src/sim/Simulation.cpp:28-30` 组合根按需装配）。
- 实测（200 tick，seed 42）：rule food=38 / stub food=411 / perceptron food=19，三策略互异，证明感知机真接线而非空转；`--ticks 20000 --seed 42 --policy perceptron --audit` → audit=ok。
- 单测由 40 个增至 50 个（`tests/unit/test_perceptron.cpp` 新增 10 个）。

红队 R2 指出这**违反** GOAL 原文：R4.2「初版严禁实现神经网络」与 §5「Phase 1 期间禁止领取，领取即违规」。红队的指出是对的：GOAL 未修订就实现，属于目标源与实现不一致。GOAL §6 流程红线本身要求"推翻本文件规则或 DECISIONS 结论必须走 supersedes ADR"，本 ADR 即为补齐该流程缺口的修订记录。

## 选项

- **A. 保持原计划，回退感知机实现**：尊重流程与"由简到难"纪律；代价是丢弃已完成的 10 个单测、CLI/组合根接线与全部实测证据，E1 扫参实验作废，且 P4 到来时大概率原样重做一遍。
- **B. 提前引入并把感知机从非目标移出，改为提前启动**（候选采纳）：以 supersedes ADR 修订 GOAL 相应条款，使目标源与实现重新一致；保留全部已完成工作，同时用硬约束防止"提前"演化为失控。
- **C. 保留代码但默认不接线**：代码留在 `src/` 必然命中 S8 的 perceptron grep 断言，门禁要么失效要么造假；代码不被 check 覆盖、无证据映射——既让代码腐烂又仍违反 GOAL 原文，三个选项中最差。

## 决定

采用 **B**，附带三条硬约束：

1. **RulePolicy 仍是默认策略**：感知机必须显式 `--policy perceptron` 才启用（当前组合根已满足：`Simulation.cpp` 仅在 `usePerceptron` 或 `policy.name=="perceptron"` 时装配 PerceptronPolicy，否则仍是 RulePolicy）。
2. **同 seed 输出必须互异**：感知机与 RulePolicy 在相同 seed 下产出不同结果，否则视为接线失败（已实测：200 tick seed 42，rule food=38 / perceptron food=19，互异）。
3. **与 RulePolicy 受同一套红线约束**：感知机 `decide` 不得引入 RNG；权重初值仅可由固定种子（`--perceptron-seed`）经自传 PCG32 在构造期确定性生成、运行期冻结；不得 include 环境层（只吃 `SensorVector`）——S4 依赖守卫对 PerceptronPolicy 与 RulePolicy 一视同仁。

## 后果

- **S8 原判定语义作废并重定义**：原「初版无神经网络（依赖守卫 + grep 断言 perceptron/neural/nnet 零命中、`IDecisionPolicy` 仅注册 RulePolicy）」自本 ADR 生效起语义作废，重定义为**「决策层可插拔：默认 RulePolicy；PerceptronPolicy 为可选策略，且两者均满足：不 include 环境层、decide 无 RNG、同 seed 输出互异」**；GOAL.md §3 的 S8 行已同步改写，验证方式为可执行命令。
- **INDEX 附录 A2 需同步改判**：A2 的「`: public IDecisionPolicy` 仅命中 RulePolicy.h」与「perceptron|neural|nnet 零命中」断言预期失效（现 `: public IDecisionPolicy` 命中 RulePolicy.h 与 PerceptronPolicy.h 两处）。INDEX.md 归属他人维护，本 ADR 不代改，需主代理在下一次 INDEX 更新中同步改判。
- **好处**：S13 的主体内容（第二决策实现可替换 RulePolicy）提前落地并有实测证据（三策略互异、2 万 tick 审计通过、serialize 位精确往返、10 个单测）；GOAL 与实现重新一致；E1 扫参实验由"违规产物"转为有据可查的实验记录。
- **代价与风险（诚实记录）**：P1 未走完即动用 P4 内容，"由简到难"的串行纪律被削弱；若感知机后续与 P2（S9 双范式）或 P3（S12 温度失真）发现耦合，可能返工。感知机不得反客为主：不进入 P1 出口条件，RulePolicy 仍是主验收对象；S13 的「固定种子双跑一致」复核仍保留为 P4 出口，不因提前引入而免除。
- **§1.1 R4.2 行文保留**：原文「初版严禁出现」字样保留在 GOAL §1.1（最小修订面），其判罚语义由本 ADR 改判，读者以 GOAL §4 与本 ADR 为准。

## 可逆性

高。感知机是纯可选策略：删除 `src/decision/PerceptronPolicy.{h,cpp}`、`tests/unit/test_perceptron.cpp` 与 Simulation/Cli/Config 三处接线分支即可完全回到原计划，RulePolicy 默认路径与既有 S1–S7/S9–S11 证据不受影响。不可逆部分仅剩记录事实（E1 实验数据与本 ADR）；若用户收回创新授权，走反向 supersedes ADR 即可。
