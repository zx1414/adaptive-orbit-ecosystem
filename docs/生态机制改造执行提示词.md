# 给接手模型的任务：实现自适应环绕核的下一版生态机制

你负责修改我已有的游戏仓库 **agentsim（自适应环绕核生态模拟与生存游戏）**。请以生态模拟游戏设计师、C++17 维护者和验收负责人的身份工作。最终交付是一个在现有客户端里能玩的版本。我把机制取舍写在下面，你负责实现、接线、运行、验证和如实交付。完成一阶段后直接推进下一阶段，直到 P0、P1、P2 都有结果。

## 一、先对齐我的意图和项目现状

我想看见一个能自行运转的微型生态。蓝细菌利用光照生长，是主要食物。核在局部信息下取食、移动、建造环绕器官、繁殖；几只核会争同一片食物。资源有限，所以侦察、储备和生育之间有取舍。玩家免费改变环境，后果沿生态关系传递。局部耗竭、重新定殖、谱系消失和自然灭绝都是有效结果。颜色用来辨认谱系，性能上限用来保护运行；它们都不定义生态是否成功。

当前主线为 Windows C++17 模拟器、原生 JS 前端和本地 HTTP 实时接口。设计基于 v3.0.0 的 `8959762`。可以从更新的工作树继续，先核对差异，绝不要为复现该版本重置用户工作树。保留环面、昼夜、自遮光、蓝细菌分裂及局部连线传输、移动耗能、核间聚拢与排斥、携带变异的遗传、器官脱离与接管。保留当前存档、回放、时间轴与确定性能力。

**开始操作。** 在含 `src/`、`frontend/`、`tools/` 和 `VERSION` 的仓库根目录读取 `git status --short --branch`，记录用户已有改动。读 `docs/下一版生态机制设计.md`、`CONTRIBUTING.md` 和 `HANDOVER.md`。用 `src/sim/Simulation.cpp` 的 `step` 核实生产路径，按需追到环境、感知、决策、行为和接口。第一次进度汇报用几句话交代目标、确认的旧行为、首个修改点和验收方法，然后开始写代码。若无法访问仓库，先明确缺少仓库访问，不能声称已经修改。

**取舍优先级。** 我在本轮给你的最新明确指示优先，当前玩法以本提示和配套设计为准。代码说明“现在怎样运行”，旧手册、旧 TODO 和历史报告描述过去。遇到局部注释与实际调用相反，用可达分支和可复现结果裁定现状。已有工作流中的“主代理只指挥”“打满并发”“定时夜班”不是本任务要求。技术选择可自行决定；只有涉及互斥的产品选择、需要覆盖用户数据或扩大范围时才询问我，其余可独立完成的工作继续。

## 二、P0：改正食物竞争、个体记忆和玩家事件

1. **统一摄食条件。** 当前默认会按遗传最高速度折减每口摄食量，另有默认关闭的远距离进食奖励。移除这两类修正，包括可以在普通新局重新启用旧行为的入口。实际移动依旧耗能，处理食物依旧花时间。感知、选择目标、发出取食请求和扣减库存使用同一份可食量定义；最近节点已空时可选范围内其他目标。
2. **让食物实际耗竭。** 移除每个节点固定 15 单位的不可食保底。避免按剩余量取固定比例而永远吃不光：给出可解释的最小存活结构量或最小取食单位，剩余物有明确去向。节点死亡后由邻近存活菌落通过正常生长、扩散、分裂重新定殖。全图生产者已灭绝时，只有显式播种或新开局才可重新引入。
3. **解决同时争食。** 一个模拟步内先收集对同一节点的有效请求，再统一分配。请求受摄食能力和实际储存余量限制。总需求超过库存时，按请求占比分配，采用稳定的运算顺序。分别结算从生产者取走的数量、消费者吸收的数量及损失去向，避免多个核领取同一份食物。
4. **让记忆归个体。** 当前 `Simulation` 在循环中调用同一 `policy_`，例如 `ForageBankPolicy` 将状态保存在实例成员里。逐个检查有可变记忆的策略。规则和不可变参数可以共享；觅食状态、学习历史、上一次目标等由核独立持有。新生核继承基因，行为记忆以新个体状态初始化。读取存档时恢复已存在个体的实际记忆。
5. **重做普通玩法中的干预。** 撤去直接给全体核加能量的“收获”、扣余额的“寒冬”、只惩罚富核的“瘟疫”、直接追加生产者的“藻华”。普通 UI 和实时接口同时更新；过期命令应有明确反馈。保留免费调控。寒冬在有限模拟时间里改变环境条件，到期解除自身影响；玩家期间修改的基础环境设置仍有效。藻华由生长和分裂产生，玩家播种属于独立且明确的外部输入。

**P0 验收**

| 编号 | 构造条件 | 必须观察到 |
|---|---|---|
| A1 | 两个独立的等价场景中，核都静止，食物、空余容量、消化与其他条件相同，仅遗传最高速度不同 | 当步实际取走量和吸收量都一致。改变上一餐的位置也不会带来加成。 |
| A2 | 两个核同时请求 2 和 6 单位，节点只有 4 单位可食，其他限制均未触发 | 分别取到 1 和 3，节点只扣 4。颠倒核的遍历顺序，按个体身份对齐后结果相同，允许项目既有浮点容差。 |
| A3 | 一个已无可食组织的节点比仍有食物的节点更近；另设完全吃空且没有外来播种的区域 | 正常感知和行为能选中可食目标。局部恢复有可追溯的繁殖来源；全图无生产者时不会自动刷新食物。 |
| A4 | 用有记忆的策略，让两个核收到会触发不同状态的局部输入，再分别单独运行同样的输入序列 | 两个核各自的状态与各自单独运行一致；后代没有继承亲代最近一次觅食经历。 |
| A5 | 从真实客户端触发寒冬，再用对应的接口路径调用；检查触发瞬间、后续模拟步和到期时刻 | 触发本身只改变环境状态。后续生存差异来自正常代谢和食物变化；旧事件不能通过普通接口绕过新规则。 |

## 三、P1：让死亡、养分和再生形成循环

现版死亡入口要求核可用能量已经耗尽，却从剩余正能量中提取 30% 生成尸体；正常饿死时这笔量为零。请把“可支配能量”和“构成身体的物质”分开。第一版只设计**一种抽象养分**，在区域中区分残骸和可吸收养分。用随模拟时间推进的局部分解过程即可。

明确初始养分存量与各处持有量。菌落形成新组织时从当地取养分；核吃下组织后，物质移入核体或回到环境；繁殖从亲代分配材料和能量；核或菌落死亡后，剩余身体材料在原地形成残骸；分解逐步释放当地养分。显式施肥、播种等外部输入须单列。生物的呼吸、移动损耗继续进入能量账。残骸和养分不能替代光照凭空给生产者增加可用能量。材料覆盖器官时也要有明确归属，避免在核、球、残骸之间重复记账。

**P1 验收**

| 编号 | 构造条件 | 必须观察到 |
|---|---|---|
| A6 | 让有身体材料、活动储备耗尽的核经正常更新死亡 | 原位置产生非零残骸；其他区域不直接收到养分。随后若干步能看到残骸下降、当地养分上升，且去向可核对。 |
| A7 | 关闭外部物质输入，覆盖取食、排出或未同化部分、繁殖、死亡、分解、重新吸收 | 所有物质库的总和在数值容差内保持初值。显式施肥的对照中，总量变化等于外部投入。能量账独立闭合。 |
| A8 | 分别给缺养分和养分充足的等价菌落提供光照，再检查一个无光、无可用能量储备的节点 | 养分限制新组织的形成；无光且无能量储备的节点不能仅靠添加养分长出新组织。 |

## 四、P2：做实环绕核的器官

1. **侦察球。** 从每个受控侦察球的真实世界坐标采样邻近可食目标，经有效控制距离回传，合并重复目标。使用环面最短距离。保留核已有的近身感知。资源球不提供额外视野。
2. **资源球。** 摄入后的富余能量确实转移到有空位的资源球，缺粮时按有限速率取回。转入、取出、脱离、拾取、死亡、回收各有明确去向。容量和已存储数量分别表示，核和球不能同时持有同一份能量。自由球保留脱离时的余额，后续可按自然衰减规则变化。移除仅因换主而向原主追加的固定罚款。
3. **造球与繁殖。** 正常新局中的第一批器官由核以自身资源建造；在同一阶段撤去蓝细菌产球。生物能在侦察、储备和繁殖之间作出由自身状态与遗传倾向影响的取舍。先完整接通侦察球和资源球；护盾球保留类型与已有数据兼容，隔热重设计作为后续建议，本轮不新增战斗或装备系统。

**P2 验收**

| 编号 | 构造条件 | 必须观察到 |
|---|---|---|
| A9 | 核与食物都不动，食物在核近身感知范围外。让受控侦察球分别靠近、远离食物，再验证跨环面边界的情形 | 目标只在实际探测且能回传时出现。换成资源球失去该项探测能力。 |
| A10 | 把已知数量的能量存进球、取回一部分、脱离并由另一只核接管；对照一颗空球 | 按步骤核对两只核和球的能量。接管保存余量；实际发生的耗散能解释差额。满球与空球的生存后果不同。 |
| A11 | 用普通开局与正式行为路径，从无球状态运行，观察有足够资源时的建造选择，同时覆盖一次繁殖 | 核可以付费获得器官；建造占用本可用于繁殖的资源，蓝细菌不再掉落成品球。只在单测里手工创建对象不算接通。 |

## 五、实施与数据保护

- 沿用环境、感知、决策、行为、账本的职责。决策读取观测并输出动作；行为层负责核与球的状态变更，环境层管理菌落与区域，模拟主循环协调同帧结算。复用原有接口、随机数生成器 PCG32 和前端。将新增状态接入存档、恢复、时间轴检查点以及需要展示的实时快照。
- 把每阶段拆成可运行的小改动。改一条规则就垂直追踪到正常入口：配置或控件、运行时映射、模拟步、状态输出以及对应测试。前端源码有改动就重新生成项目原有 bundle。使用运行中真正读取的值，警惕只改说明、存在两个配置默认值、只在测试构造器生效或旧前端继续发送已删除命令。
- 保留同一新规则版本下同种子和相同输入的确定性。旧版本的总能量、种群数、色相分散度仅作比较。规则变化引起数值变化时，给出可以定位到该机制的解释。旧测试若明确固定了被替换的规则，逐项更新成新的行为断言，保存原有保护意图。禁止跳过测试、放宽误差去消除失败或只替换金标准数值。
- 新旧存档要能辨别。新档保存和恢复后须逐步一致。如果老档缺少养分或行为记忆，只有在能明确解释初始分配时才提供显式转换，并输出到新档；否则在读取时提示旧档版本及受支持的打开方式。两种路径都不能改写原件。测试用新建临时目录或存档副本；维护用户现有工作树与存档。
- 本轮只实施 P0–P2。保留旧版源码作参考。不要顺手整理全仓库、重写框架、创建第二套模拟器、拓展物种或疾病系统、添加影响力预算、安排定时夜班或发布新版本。保持既有工程依赖；需要更大产品决策时说明具体冲突。
- 交付方式是本地可运行的工作树改动。不要执行整树重置、强制检出、批量清理未跟踪文件，也不要代我提交、推送、打标签或覆盖 `release/`。如需验证桌面体验，用与本次构建配套的前端和可执行文件在临时目录验证。
