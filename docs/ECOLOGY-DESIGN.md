# 生态机制设计（R3 目标：让系统真的"自然"）

## 问题诊断（实测，2026-11-01 01:30）

```
seed 42 : 20000 tick  nuclei=24  total_energy=12361.7  audit=ok
seed 7  : 20000 tick  nuclei=24  total_energy=12643.6  audit=ok
seed 123: 20000 tick  nuclei=24  total_energy=12759.4  audit=ok
```

三件事同时证明系统**不自然**：

1. **核数恒为 24** —— 三个不同种子都撞到同一个数。这不是承载力，这是 `kReproCap=24`
   硬编码。真实生态的种群数应该是浮动的、和资源供给相关的。
2. **种群在 tick 2000 就打满上限并锁死** —— 时间序列实测：
   ```
   tick   2000  4000  6000  8000 10000 12000 14000 16000 18000 20000
   核数     24    24    24    24    24    24    24    24    24    24
   总能量 14249 14807 15231 13131 13035 13819 14403 14698 13704 12362
   死亡      4     4     4     4     4     4     4     4     4     4
   ```
   能量确实在 12k~15k 之间波动（不是单调膨胀，这点比我预期好），但**核数从第 2000 tick
   起就一动不动**。这意味着整个 20000 tick 里，除了最初 4 次死亡，**生态零事件**。
   没有出生、没有死亡、没有竞争、没有替代——这不是生态，是 24 个核在一个静态罐头里。
3. **三者数字几乎相同** —— 说明动力学被常数主导，随机性没有产生分歧。

## 根本原因：缺一个负反馈

现在能量链是：`光 → 蓝细菌（注入）→ 核（搬运）→ 耗散`。
问题是**注入端没有负反馈**：光强由 tick 决定，与蓝细菌数量无关。所以蓝细菌永远吃得饱，
核永远有得吃，唯一的上限是 `kReproCap=24` 这个外生常数。

**自然界的负反馈来自资源被消耗**：生产者多了 → 互相遮光 → 单位产量下降 →
生产者数量回落 → 光重新充足。这叫自疏（self-thinning），是真实植被最基本的规律。

## 三个必须实现的自然机制

### 1. 自遮光（局部光竞争）——生产者层的负反馈
每个蓝细菌节点接收到的光不是全局光强，而是**被邻居遮蔽后的局部光**：
```
localLight(node) = globalSun * exp(-shadeK * Σ_{j in shadeRadius} exp(-d_ij^2 / (2σ^2)))
```
- `shadeK` 默认 0.02，`shadeRadius` 默认 60（= linkRadius），σ = shadeRadius/2
- 用已有的 O(n²) 邻居循环（linkTransfer 已经在做），**零额外开销**
- 效果：节点密集处光合骤降 → 分裂停滞 → 自然稀疏
- **这一条不做，能量永远膨胀**

### 2. 营养循环（尸体分解）——能量闭环
核死亡时，它的能量**不是全部耗散**，而是：
- 70% 耗散（`dissipate("death")`，热力学损失）
- 30% 转成"营养脉冲"，在死亡位置上**为最近的蓝细菌节点充能**（`ledger.transfer`，零和）
- 效果：核密集区死后长出一片蓝细菌 → 吸引新的核 → 形成真实的斑块动态（patch dynamics）
- 这是真实的养分循环（动物尸体 → 分解者 → 植物）

### 3. 捕食的真实代价（处理时间）
现在核可以无限吃。真实捕食者有**处理时间**（handling time）：
```
吃掉一个节点后，该核进入 digestionCooldown 帧（= ceil(1 / (0.5 + cyanoDigestion)))
cooldown 期间不能再吃
```
- `cyanoDigestion` 高 → cooldown 短 → 吃得多
- 但 `cyanoDigestion` 与 `maxSpeed`/`maxAccel` 在基因组里**独立变异**，
  于是自然分化出两套策略：
  - **"快跑少吃"**：高 maxSpeed，低 digestion，到处找节点吃一口就走
  - **"慢爬猛吃"**：低 maxSpeed，高 digestion，蹲守一片节点吃完再走
- 这就是旧版 `cyanoConversionMode` 想要的涌现，但旧版用的是**外在公式惩罚**，
  我们用的是**内在生理约束**（更自然）

## 需要同时改的常数

| 常数 | 现值 | 改成 | 理由 |
|---|---|---|---|
| `kReproCap` | 24（硬上限） | **删除**，改用 `maxNuclei` 护栏 = 300 | 种群数必须由能量决定 |
| `kReproEnergyGate` | 固定 | 基因 `energyThreshold` | 已经是 R2 内容 |
| `maxNodes`（蓝细菌） | 64（性能护栏） | 保持 64 但**加注释**：这是性能护栏不是生态上限；因为自遮光生效后生态上限会 < 64 | 自遮光接管后护栏不再生效 |
| `kGrazeChance/kGrazeFraction` | 0.25 / 0.04 | **删除**，改基因驱动 | R2 已列 |
| 光合 `photosynthesisRate` | 1.0 | 0.35 | 自遮光后单位产量要下调，总量才平衡 |
| `metabolismRate`（蓝细菌） | 0.02 | 0.05 | 让不繁殖的节点会自然死亡 |
| 核 `respirationBase` | 0.008 | 0.012 | 提高基础代谢，让"活着"有真实成本 |

## 调参方法论（不许手调）

**不许**"试一个数、跑一次、不行再试"——那是把常数当魔法，违反 GOAL-ECOLOGY §二.5。

正确做法：**做一个参数扫描工具**，一次跑 30 组参数，看哪组满足判据。
工具要求：
- `tools/sweep.ps1`：接受参数名与候选值列表，对每组跑 20k tick，输出 CSV（参数组合 → 稳态指标）
- 指标：末态核数、末态总能量、能量斜率、蓝细菌末态数、核数标准差/均值、基因标准差
- 主代理读 CSV 决策，**不是**凭感觉

## 观测工具（没有观测就没有涌现）

涌现是**看**出来的，不是断言出来的。必须做一个 `--trace` 的增强版：
```
agentsim --no-render --ticks 50000 --seed 42 --trace out.json --trace-interval 50 --trace-genome
```
- `--trace-genome`：每帧把每个核的 24 个基因 + hue 全导出来（体积大，只用于分析）
- 配套 `tools/analyze.mjs`：读 trace，输出
  - 每个基因的种群均值/标准差随时间的曲线（24 条）
  - hue 的圆标准差随时间
  - 核数/蓝细菌数/总能量三线图
  - 末态 maxSpeed × energyThreshold 散点图（看分群）
  - **自动判定**：6 条判据各自 PASS/FAIL

**这是明天验收的核心交付物**：一条命令跑出图 + 一份自动判据报告。

## 实施顺序（R3）
1. 自遮光（生产者负反馈）—— 最高优先，没有它一切白搭
2. 删除 kReproCap + 捕食处理时间 —— 让种群和策略能分化
3. 营养循环 —— 让空间结构有记忆
4. 参数扫描工具 —— 用数据定常数
5. trace-genome + analyze.mjs —— 观测
6. 用扫描结果定标，跑 100k tick 验收


## 附：来自前端实现者 D 的实测发现（2026-11-01 01:20）

D 在写演示数据时实际撞到一个**生态死局**，值得记下来：

> 繁殖阈值 Init 从 140~190 改成 110~160、初始能量 100~160、cap 240——因为
> **cap=120 < 阈值下限时核永远无法繁殖**（实际撞到：12 核 → 只死不生 → 4 核）。

这不是前端问题，是**基因组必须校验的硬约束**：

```
energyThreshold <= cap * 0.9     // cap = nativeCap + Σ resource.cap
```

否则该核的基因组直接是"不育"的。真实生态里不育个体确实存在（而且会被淘汰），
但如果**初始种群里所有核都不育**，那就是初始化 bug，不是选择。

**处理方式**（写进 R2 规格）：
- `genomeRandomize` 不做这个校验（自然变异可以产生不育个体，这是选择材料）
- 但 `Simulation::spawnNuclei` 的初始种群**必须重掷**直到所有核都可育
- 或者更简单：把 `energyThreshold` 的 Init 上限压到 `nativeCap * 0.8` 以下

D 还独立测了演示数据的生态行为（虽然不是真实模拟器）：
- 核 12→峰 16→稳 9~12（波动，无灭绝无爆炸）
- 蓝细菌 48→峰 ~85→40~60
- hue 终局散布 157°（多样性未塌缩）

这说明**设计方向是对的**：当承载力和能量是反馈关系而不是常数时，种群自然会波动。
真实模拟器需要的只是把 kReproCap 那个常数拆掉。
