## 1. 背景与问题

v2.3.1 的生态模型是"蓝细菌（环境生产者）→ 核（消费者与唯一决策体）→ 小球（器官，绕核旋转）"。
v3 的 M1 是推倒重来，把生态本体换成了"静止生产者 + 独立 Agent 追食物"，丢掉了轨道物理、三型器官、
遗传参数与蓝细菌网络；原始设计要求的 `agent_mode` 共存开关从未实现。

M5 阶段 1–5 已把生态语义搬回四层架构：环境层蓝细菌、核与球的轨道物理、球内能量、侦察采样、
决策与繁殖均已落地。核心矛盾由此从"模型不对"转为**"机制正确但不可持续"**：默认参数下
12 个核在约 1500 tick 内吃光 400 个蓝细菌，随后全部饿死；同时遗传维度只有 8 项参数，
尚不足以支撑"通过变异涌现生态"这一最初意图。

## 2. 最终目标

- G1：模拟跑的是"阳光 → 蓝细菌 → 核 → 小球"的完整链路，核是唯一决策体，小球不决策。
- G2：小球绕核公转而非振荡，且轨道半径由核的遗传参数决定。
- G3：能量真实存放在资源球内；球脱离只改归属、能量随球移动、可被任意核拾取。
- G4：蓝细菌光合是唯一初级能量注入；每 tick 审计覆盖蓝细菌、核、球三方。
- G5：核的遗传参数可变异，且种群在默认参数下长期共存而不灭绝。
- G6：轨迹导出能让外部前端画出"球绕核"的从属关系。
- G7：存档读档后续跑与不中断运行逐位一致。

## 4. 范围边界（非目标）

- **不做 v2 的 mod 兼容与逐字节基线**：v2 的实体模型与协议和新生态不兼容，保留它只会绑住重构。
- **不做 `agent_mode` 双模式共存**：双模型正是本次要消除的东西；共存会让两套状态互相污染。
- **本期不做核间战斗（`nucleusCombat`）**：依赖攻击范围/强度基因与球损失规则，等基础生态跑通再定。
- **护盾球只保留类型与计数，不实现功能**：护盾语义（拦截/撞击）属于战斗重做，提前做会返工。
- **本期不做神经网络策略 `NNetPolicy`**：Observation/Action 契约未稳定前做网络等于重写。

## 6. 约束与红线

- **能量红线**：光合是唯一 `injectPrimary`；所有能量变化经 `EnergyLedger`；每 tick 审计，
  失败即终止（退出码 3）。任何绕过账本直接改能量字段的写法视为失败。
- **架构红线**：世界 → 探测 → 决策 → 行为严格单向。探测不调用策略；决策不读世界、不使用 RNG；
  行为是唯一写实体状态的层。`tools/check.ps1` 的依赖守卫必须通过。
- **确定性**：单线程、PCG32、固定迭代顺序、稳定 `EntityId`。禁止 `rand()` 与时间种子。
  传感器噪声必须来自 `Simulation` 持有的 PCG32。
- **零第三方依赖**，MSVC `/W4 /WX /permissive- /utf-8` 零警告。
- **错误码契约**：2 参数错误、3 审计失败、4 I/O 失败、5 快照无效。
- **不得修改 `frontend/`**：那是用户独立维护的前端；C++ 侧只保证 JSON 契约。

## 7. 关键术语

- **蓝细菌（CyanoNode）**：环境层的生产者，唯一进行光合的实体。
- **核（Nucleus）**：消费者与唯一决策体，携带可遗传参数。
- **小球（Ball）**：核的器官，不决策；类型为 Resource/Scout/Shield，只决定功能不决定力学。
- **轨道半径（orbitRadius）**：核的单一遗传参数，所有自有球共用，靠球间排斥散开。
- **菌落容量（colonyCap）**：`nativeCap + Σ(资源球 cap)`，超出部分被销毁并记 `CapOverflow`。
- **侦察采样**：每个侦察球独立采样，读数随距离衰减并叠加 PCG32 噪声，核取最显著报告。
- **审计恒等式**：`injected - dissipated == Σ蓝细菌 + Σ核 + Σ球`。
