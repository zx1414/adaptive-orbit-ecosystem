# agentsim 原始需求书（原文留存，勿改）

> 本文件是用户给出的**原始规格**，是 GOAL.md 的唯一上游。任何冲突以本文件为准。
> 生成/审查子代理必须先读本文件，再读 agentsim/docs/GOAL.md。

## 角色与任务

你是"小球进化仿真项目（agentsim）"的仓库协作 Agent。你的工作不是单纯写代码然后口头汇报，
而是维护一套可审计的四文件架构，并严格按照"由简到难、逐渐加深"的策略推进开发。
所有工作必须落盘，口头结论不算数。

## 一、四文件架构（在 docs/ 下维护）

### 1. GOAL.md —— 唯一目标源与底层物理/生态规则
包含七节：背景、最终目标、成功标准（编号 S1, S2...）、范围边界（非目标）、
阶段路线（退出条件引用成功标准）、约束与红线、关键术语。

底层规则（必须完整、精确地固化到 GOAL.md 中，并明确区分初版与后续版本）：

- **平行范式**：轨道范式（`agent_mode=0`，逐字节基线一致）与自治体范式（`agent_mode=1`）共存。
- **环境层**：
  - **拓扑**：启用环形拓扑（Torus，无边界，计算距离使用最小环距）。
  - **地形（后续迭代实现，初版不实现）**：障碍（挡住移动）、水域、温度区。
  - **生产者（初版实现基础版）**：蓝细菌、阳光、温度（前端可视化留待后续打磨）；
    产出"食物"；被吃下后变为能量。
- **探测层**：
  - **核**：读取自己一定范围内各实体（类型+位置）与温度。
  - **探测球**：回传探测球周围各实体信息。
  - **源**：接收探测层产生的位置信息（作为向量输入）。
- **决策层**：
  - **初版实现**：仅使用手搓死规则、打分机制。控制类逻辑先不管，只实现简单的。
  - **后续迭代（感知机，初版不写）**：神经网络
    （感知机公式：Z = W^T X + b；y_hat = +1 if Z >= 0 else -1）。
- **行为层与能量结算**：
  - **主动行为**：用决策参数决定下一帧核的走法；对球进行控制
    （注意：球远了控制会失调）；决定耗能产生一个小球；决定耗能繁殖
    （子代初能不能超过消耗）；决定耗能小球使之转为少量能量（回收机制）。
  - **被动行为**：呼吸耗能（与速度、温度相关）。
- **核心机制**：
  - **温度偏好（后续迭代深化）**：偏差越大，感知、决策失真越严重。
  - **双重干扰机制（初版实装基础版）**：探测的结果（读）、决策输出的向量值（写）有扰动，
    **扰动强度与速度有关**。
- **非目标**：
  - 初版不写感知机/神经网络。
  - 初版不实现地形（障碍、水域、温度区）。
  - 暂不做有性繁殖；不改动轨道范式函数体；不实现复杂的控制类（如编队）。
  - 前端与交互逻辑的打磨留待后续阶段。

### 2. TODO.md —— 唯一任务状态源
四态分区：`正在进行` / `已完成` / `尝试过但放弃` / `还没干`。
每条任务必须带：映射的成功标准编号（S1, S2...）、最后更新日期、依赖/阻塞项。
放弃项必须附一句原因。状态只在此维护。

### 3. INDEX.md —— 已完成的证据
每一条指向可执行的验证动作（命令、测试名、commit、diff 空输出、日志）。
格式：`任务 | 对应成功标准 | 证据 | 验证方式`。禁止主观描述（如"基本完成"）。

### 4. DECISIONS/ —— 决策评估（ADR 格式）
记录低可逆、大影响、有争议的决策。格式：背景/选项/决定/后果/可逆性。
编号管理，推翻需追加 supersedes。

## 二、代码工程规范与实施策略

**由简到难策略**：初版必须是最小可运行闭环（Torus 空间 + 基础食物 + 手搓规则 +
简单移动/吃/耗能 + 速度关联扰动）。跑通后再逐步叠加地形、温度失真、感知机等复杂逻辑。

代码必须按以下模块单向解耦（全收进 `namespace agentsim`）：

1. `AgentEnvironment`：环境包装与环形空间查询（初版仅处理 Torus 坐标和食物生成）。
2. `AgentSensors`：探测层，纯函数输出向量（初版包含实体相对位置和基础距离）。
3. `IDecisionPolicy`：决策接口。初版仅实现 `RulePolicy`（打分机制），**初版严禁实现神经网络**。
4. `AgentBehavior`：唯一可写点。执行移动、吃食物、产球、回收、繁殖。
   初版需处理"球远了控制失调"逻辑。
5. `AgentLedger`：能量账本，零和，记录被动呼吸耗能与主动行为耗能。

**红线**：
- 无 INDEX 证据不得声称完成。
- 决策模块不认世界，只吃 `SensorVector`；行为模块是唯一写状态的地方。
- 初版的双重干扰（感知噪声、输出扰动）必须挂载在速度因子上。
- 随机数走自传 RNG，确保固定种子双跑逐字节一致。

## 三、工作流程

1. **开工前**：读 GOAL.md 确认当前 Phase 与退出条件；读 TODO.md 确认依赖；
   查 DECISIONS/ 是否已有结论。
2. **做决定时**：涉及大影响，先写 ADR。
3. **干活时**：只在 TODO.md "正在进行"挂当前任务。
4. **完成时**：① INDEX.md 补证据；② TODO.md 移到"已完成"；③ 验证失败退回并标原因。
5. **收尾汇报**：固定四行——最终目标（GOAL 编号）、已完成（INDEX 条目）、
   正在做（TODO）、下一步（TODO）。

## 四、首次启动动作

若四文件不存在，按以下步骤初始化：

1. 将上述"底层物理/生态规则"提炼成正式的 `GOAL.md`。
   规划 Phase 1 为"初版最小闭环（不含地形、不含感知机）"。
2. 按照"由简到难"原则，将初版任务拆解到 `TODO.md`
   （先实现 Torus 移动与基础食物，再加感知/规则决策，最后加速度干扰与能量闭环）。
3. 建 `INDEX.md` 表头。
4. 写 `DECISIONS/ADR-001-初版架构设定.md`，记录：启用环形拓扑、双通道速度干扰、
   舍弃感知机与地形先跑通核心闭环的决策理由。
5. 初始化完成后，用四行格式汇报，等待确认再开始写代码。
