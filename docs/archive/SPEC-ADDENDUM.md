# 用户规格补充（2026-10-31 13:00，优先级高于 GOAL.md）

> 这是用户对本轮四个问题的明确回答。任何实现与此冲突，以此为准。

## S-A 探测：每个核独立探测，噪声在**单位级**加，融合交给决策层

- **每个核就是独立的**。核之间**没有**跨单位融合，也没有共享观测。
- 后续会有**探测球**——那时才会出现"对同一个实体的多次读数"。
- 正确做法：
  1. 每个传感器（核 / 探测球）**各自探测**，**各自**按自己的误差把噪声加进去；
  2. 加完噪声后，把向量传给决策层；
  3. **同时把传感器自身的速度、温度也传过去**；
  4. **决策层自行决定**"看到同一实体时怎么加权"。
- 理由：便于后续神经网络处理（网络自己学权重，而不是感知层写死融合公式）。

**当前实现的偏差**：
- ❌ 噪声是"每核每帧抽一次，三个候选共用同一偏移"——这会让候选间的相对关系不变，
  噪声只做整体旋转，等于没有干扰排序。应改为**每个候选独立抽样**。
- ❌ 感知层没有把"传感器自身速度/温度"作为**可被决策消费的独立维度**传出去
  （s[10..12] 是速度，s[16..17] 是温度——需确认决策层能真正读到并用于加权）。
- ✅ 没有跨单位融合，这一点符合规格。

## S-B 资源球是仓库：提升核的总储能空间

- 资源球 = 核的**储能仓库**。核拥有的球越多/越大，**总储能空间**越大。
- 当前 `Nucleus.cap = 200.0` 是**硬编码常量**（`Simulation.cpp:108`），球完全不参与容量计算。
- 应改为：`colonyCap = nativeCap + Σ(自有资源球.cap)`，即核的容量是**派生量**。

## S-C 球受力学控制，自然脱离；脱离后是**自由球**，可被别人捡走（选 A）

- 球**受力学控制**（轨道/弹簧/切向驱动），所以**自然会脱离**——不需要额外的"掉落"指令。
- 脱离后的球：
  - **能量仍在球里**，随球移动（**A 语义**：核失去的是**支配权**，不是能量蒸发）；
  - 变成**自由球**（`ownerId = 0`），位于世界坐标；
  - **可以被任意核捡走**（`adopt`），`ledger.transfer(ballId, newOwnerId, ...)` 零和；
  - 自由球会随时间衰减（`ballDrift` 已有机制），这才是真正的"掉落损失"。
- **不是 B 语义**：脱离瞬间不调用 `dissipate` 把能量蒸掉。

## S-D 核可以以能量代价给范围内的球施加加速度

- 核能对**范围内**的球（自有球 + 自由球）施加**加速度**，代价是消耗核的能量（走账本）。
- 这是核影响球运动的手段，区别于"轨道参数"——是**主动施力**，不是被动跟着转。
